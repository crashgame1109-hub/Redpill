# REDPILL backend

Бэкенд для Mini App REDPILL: общий раунд для всех игроков (сервер ведёт единый
таймер и честно генерирует исход), реальный баланс, пополнение через
**Telegram Stars** и **крипту** (Crypto Pay API / @CryptoBot), чат, история транзакций.

## Что уже работает
- Проверка подлинности Telegram Mini App (валидация `initData` по HMAC)
- Баланс игрока в SQLite (`users`), полная история транзакций (`transactions`)
- **Общий раунд-луп** (`src/roundLoop.js`) — один таймер и один честно
  сгенерированный (SHA-256 commit/reveal) исход на ВСЕХ подключённых игроков
- **Реальные ставки** через WebSocket — списываются/начисляются на серверном
  балансе, видны всем подключённым в реальном времени
- **Общий чат** — сообщения ретранслируются всем подключённым
- Буст новичка (первые 7 раундов ×1.98) считает сервер по колонке `rounds_played`,
  не клиент — подделать нельзя
- `POST /api/topup/stars` — создание инвойса на Telegram Stars
- `POST /api/topup/crypto` — создание инвойса на USDT/TON через @CryptoBot
- Вебхуки, которые реально зачисляют монеты после подтверждения оплаты
- Идемпотентность — повторный вебхук от Telegram/CryptoBot не задвоит зачисление
- **Вывод средств** (`POST /api/withdraw`) — списывает баланс сразу, ставит заявку
  в очередь на ручное подтверждение (защита от мошенничества на старте)
- **`/admin/withdrawals`** — просмотр очереди и подтверждение/отклонение заявок,
  защищено секретным токеном (`ADMIN_TOKEN`); подтверждение реально отправляет
  крипту через `transfer` в Crypto Pay API
- **Протестировано end-to-end**: два независимых клиента через реальные WS-соединения
  видят один раунд, ставки друг друга в реальном времени, честность подтверждена
  (раскрытый сид сходится с ранее опубликованным коммитом), чат долетает; вывод
  средств проверен по всем сценариям (мин. сумма, недостаточный баланс, защита
  админ-эндпоинта, возврат баланса при отклонении, защита от повторной обработки)

## 1. Установка

```bash
npm install
cp .env.example .env
```

Заполни `.env`:

| Переменная | Где взять |
|---|---|
| `BOT_TOKEN` | [@BotFather](https://t.me/BotFather) → твой бот → API Token |
| `CRYPTO_PAY_TOKEN` | Открой [@CryptoBot](https://t.me/CryptoBot) → Crypto Pay → My Apps → Create App |
| `PUBLIC_URL` | Публичный HTTPS-адрес ЭТОГО бэкенда после деплоя (см. ниже) |
| `CORS_ORIGIN` | HTTPS-адрес фронтенда (Mini App) |
| `TELEGRAM_WEBHOOK_SECRET` | Придумай случайную строку — защита от поддельных запросов к вебхуку |
| `COINS_PER_STAR` / `COINS_PER_USDT` | Твоя экономика — сколько игровых монет за 1 Star / 1 USDT |

## 2. Локальный запуск (для теста)

```bash
npm run dev
# сервер поднимется на http://localhost:8080
curl http://localhost:8080/health   # должен вернуть {"ok":true}
```

Для локального теста вебхуков используй туннель (например `ngrok http 8080`) и
временно пропиши его https-адрес в `PUBLIC_URL`.

## 3. Деплой на сервер

### Вариант А — Docker (проще всего)

```bash
git clone <твой-репозиторий> redpill-backend
cd redpill-backend
cp .env.example .env   # и заполни как выше
docker compose up -d --build
```

### Вариант Б — вручную на VPS (Ubuntu)

```bash
# Node.js 20
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs

# сам проект
git clone <твой-репозиторий> redpill-backend
cd redpill-backend
npm install --omit=dev
cp .env.example .env   # и заполни

# держим процесс живым через pm2
sudo npm install -g pm2
pm2 start src/server.js --name redpill-backend
pm2 save
pm2 startup   # выведет команду — выполни её, чтобы pm2 поднимался при перезагрузке сервера
```

### Вариант В — Railway

Railway сам подхватит `Dockerfile` и `railway.toml` из репозитория — компилировать
`better-sqlite3` вручную не придётся.

1. Залей папку `redpill-backend` в GitHub-репозиторий (Railway проще всего деплоит из GitHub).
2. [railway.app](https://railway.app) → **New Project** → **Deploy from GitHub repo** → выбери репозиторий.
3. **⚠️ Обязательно добавь Volume**, иначе база данных обнулится при следующем деплое:
   Service → **Settings** → **Volumes** → **Add Volume** → mount path `/app/data`.
   Без этого шага SQLite-файл живёт на эфемерном диске контейнера и стирается
   при каждом передеплое — потеряешь все балансы и историю.
4. Service → **Variables** → добавь все переменные из `.env.example`
   (`BOT_TOKEN`, `CRYPTO_PAY_TOKEN`, `CORS_ORIGIN`, `COINS_PER_STAR`, `COINS_PER_USDT`,
   `TELEGRAM_WEBHOOK_SECRET`; `DB_PATH` можно оставить по умолчанию — совпадает с mount path).
   Переменную `PORT` не трогай — Railway подставляет её сам.
5. После первого деплоя Railway выдаст домен вида `your-app.up.railway.app`
   (или подключи свой домен в Settings → Networking). Впиши его в переменную
   `PUBLIC_URL` (с `https://`) и сделай **Redeploy**, чтобы бэкенд узнал свой публичный адрес.
6. Проверь: `https://your-app.up.railway.app/health` → `{"ok":true}`.
7. Зарегистрируй вебхук Telegram — этот скрипт просто дёргает Bot API снаружи,
   выполнять его на самом Railway не обязательно, достаточно локально:
   ```bash
   # локально, с .env где BOT_TOKEN и PUBLIC_URL = твой Railway-домен
   node scripts/setWebhook.js
   ```
8. В [@CryptoBot](https://t.me/CryptoBot) → Crypto Pay → My Apps → Webhooks укажи
   `https://your-app.up.railway.app/webhook/cryptopay`.

### HTTPS обязателен

*(Если деплоишь на Railway — у тебя уже есть HTTPS из коробки, этот раздел только для ручного VPS.)*

Telegram не откроет ни Mini App, ни вебхук без валидного HTTPS-сертификата.
Проще всего — Caddy (сам получает сертификат Let's Encrypt):

```
# /etc/caddy/Caddyfile
your-backend-domain.com {
    reverse_proxy localhost:8080
}
```

```bash
sudo apt install caddy
sudo systemctl restart caddy
```

Либо nginx + certbot, если уже используешь nginx.

## 4. Регистрация вебхука в Telegram

После деплоя (когда `PUBLIC_URL` в `.env` указывает на реальный HTTPS-адрес):

```bash
node scripts/setWebhook.js
```

Это скажет Telegram слать апдейты об оплатах на `PUBLIC_URL/webhook/telegram`.

## 5. Настройка Crypto Pay вебхука

В [@CryptoBot](https://t.me/CryptoBot) → Crypto Pay → My Apps → твоё приложение →
Webhooks → укажи `https://your-backend-domain.com/webhook/cryptopay`.

## 6. Подключение фронтенда

В `index.html` игры пропиши:

```js
const BACKEND_URL = 'https://your-backend-domain.com';
```

Это автоматически выключит демо-режим (`SOCIAL_DEMO`) и активирует реальные
запросы к бэкенду для баланса и пополнений (окно "+" рядом с балансом).

## 7. Проверка перед реальным запуском

- [ ] `/health` отвечает `{"ok":true}` на боевом домене
- [ ] Тестовое пополнение Stars проходит и монеты реально зачисляются
- [ ] Тестовое пополнение крипты (можно на `testnet` через `@CryptoTestnetBot`) проходит
- [ ] Повторный вебхук (например, ретрай от Telegram) НЕ зачисляет монеты дважды — проверено идемпотентностью по `provider_id`
- [ ] `.env` не закоммичен в git
- [ ] Прочитал раздел про лицензирование азартных игр в своей юрисдикции — это НЕ техническая деталь, а юридическое требование

## WebSocket-протокол (`/ws`)

Клиент → сервер:
```json
{"type":"auth","initData":"..."}
{"type":"bet","side":"red","amount":100}
{"type":"chat","text":"привет"}
```
Сервер → клиент:
```json
{"type":"state", ...}           // при подключении — текущее состояние раунда (в т.ч. посреди фазы)
{"type":"auth_ok","tgId","username","balance","payoutMult","boostLeft"}
{"type":"round_start","nonce","commitHash","tBet","tLock","tSpin","tResult"}
{"type":"round_lock","nonce"}
{"type":"round_spin","nonce","outcome"}
{"type":"round_settle","nonce","revealedSeed","outcome","results"}   // всем — без сумм выигрыша
{"type":"balance","balance","win","payout","payoutMult","boostLeft"} // только самому игроку — приватно
{"type":"bet","nonce","id","who","side","amount"}                    // всем — чужая ставка видна
{"type":"chat","who","text","ts"}
{"type":"error","context","message"}
```

## Вывод средств — как подтверждать заявки

**⚠️ Прежде чем включать вывод для реальных игроков:** это меняет юридический
статус проекта — почти везде вывод реальных денег из игры на удачу требует
лицензирования азартных игр и часто KYC/AML-проверок. Здесь нет юридической
консультации, просто важно знать это заранее, а не постфактум.

1. Задай `ADMIN_TOKEN` в `.env` — любая длинная случайная строка, это твой
   личный пароль к очереди заявок. Без него `/admin/withdrawals` вернёт 503.
2. Игрок подаёт заявку через кнопку "↓" в игре — баланс списывается сразу,
   заявка встаёт в очередь со статусом `pending`.
3. Подтверждать/отклонять можно либо через веб-панель (см. ниже, вкладка
   "Выводы"), либо через curl:
   ```bash
   curl -H "x-admin-token: ТВОЙ_ADMIN_TOKEN" https://твой-бэкенд/admin/withdrawals
   curl -X POST -H "x-admin-token: ТВОЙ_ADMIN_TOKEN" https://твой-бэкенд/admin/withdrawals/ID_ЗАЯВКИ/approve
   curl -X POST -H "x-admin-token: ТВОЙ_ADMIN_TOKEN" https://твой-бэкенд/admin/withdrawals/ID_ЗАЯВКИ/reject
   ```

## Админ-панель

Часть этого же бэкенда (один проект, один деплой), но открывается **как будто
отдельный сайт** — по своему домену:

1. Заведи поддомен, например `admin.твой-домен.com`, и в DNS укажи его на тот
   же сервер, где крутится основной бэкенд (тот же IP/CNAME, что и у игры).
2. Если деплой на Railway — Settings → Networking → Custom Domain → добавь
   туда `admin.твой-домен.com` вторым доменом (Railway позволяет несколько
   доменов на один сервис).
3. Задай `ADMIN_HOST=admin.твой-домен.com` в переменных окружения и передеплой.
4. Теперь `https://admin.твой-домен.com` отдаёт панель, а основной домен игры —
   как и раньше, ничего в игре не меняется.

Пока отдельный домен не настроен (`ADMIN_HOST` пустой) — панель всё равно
доступна по пути `https://твой-бэкенд/admin-panel` на основном домене.

Что видно в самой панели:

- **Сводка** — кто сейчас онлайн, что происходит в текущих раундах REDPILL и
  Reel прямо сейчас, доход в звёздах/крипте, экономика по периодам (сутки/
  неделя/месяц/всё время), разбивка по режимам (REDPILL отдельно, Reel
  отдельно), топ игроков по ставкам.
- **Игроки** — список с поиском по имени/id, клик по строке открывает полную
  карточку игрока (баланс, ставки, выплаты, пополнения, выводы, последние
  операции).
- **Транзакции** — лента всех операций с фильтром по типу.
- **Выводы** — та же очередь заявок, что и через curl выше, но кнопками.

Разбивка "по режимам" опирается на поле `mode`, которым теперь помечается
каждая ставка и выплата (добавлено вместе с админкой) — транзакции, которые
были в базе ДО этого обновления, в разбивку по режимам не попадут (но
учтутся в общих суммах "Экономика по периодам").

## Mines — общая доска (36 шариков, 3 цвета)

Полностью переделан из одиночной игры в общий раунд, как REDPILL — одна доска
на всех подключённых игроков (`src/sharedMines.js`). Выбираешь цвет (красный/
синий/зелёный), ставишь, кликаешь по общей сетке — кто первый кликнул шарик,
тот его и открыл, остальные видят вскрытие сразу. Честный множитель на каждом
клике считается **в реальном времени** по факту того, сколько шариков твоего
цвета реально осталось (не по заготовленной таблице, как раньше) — это
единственно верный подход для общей доски, где другие игроки могут "съедать"
шансы твоего цвета раньше тебя. Подробности формулы — в комментариях файла.

**Потолок глубины (`MINES_MAX_DEPTH=7` по умолчанию)** — без него честный
множитель на дальних шагах улетает в миллиарды (математический анализ: 12/12
подряд даёт ×1.2 млрд при шансе 1 к 1.25 млрд — катастрофический риск для
казино). На глубине 7 потолок ~×10200, сопоставимо со старым "Сложным"
режимом одиночного Mines.

**Протестировано end-to-end**: два независимых клиента через реальные
WebSocket-соединения видят один и тот же раунд, гонка кликов по одной и той же
ячейке разрешается корректно (первый клик побеждает, второй получает честный
отказ), сторонний наблюдатель видит вскрытия в реальном времени, множитель на
первом клике точно ×2.91 (совпадает с аналитическим расчётом день в день).

## Известное ограничение

Комбо (×3 раунда) в REDPILL пока считает баланс **локально в браузере**, а не
через сервер. Обновления баланса от сервера сделаны аддитивными (списание при
ставке / начисление выигрыша), поэтому конфликтов с Комбо нет, но если игрок
захочет реальные деньги и там — это отдельный шаг, тот же паттерн, что и для
классики/Mines, просто для другого режима.
